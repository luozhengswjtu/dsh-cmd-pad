# cmd-pad 视觉风格统一规范（对齐 better-sidebar）

> 目标：cmd-pad 无论在 better-sidebar Tab 内（主形态）还是独立抽屉（降级形态），视觉上与
> better-sidebar / DSH 宿主**无法分辨来源**。全部规则已对 `DSH-better-sidebar-main` 源码
> （v0.15.1：`src/client/sidebar.module.css`、`src/client/icons.tsx`、`src/client/theme.ts`、AGENTS.md §8）实证。
>
> 配套文档：`docs/better-sidebar-接入规范.md`（接入侧）。

---

## 1. 令牌契约（第一优先级）

### 1.1 硬规则

1. **零硬编码颜色**。所有颜色消费 DSH 语义令牌 `--dsw-alias-*`；皮肤系统覆盖什么就跟随什么，
   **不做任何每皮肤适配**。
2. 每个令牌引用带兜底链：`var(--dsw-alias-X, var(--cp-X, <最终兜底色>))`——`--cp-*` 是 cmd-pad 自定义
   中间层（可选），最终兜底保证令牌全灭时面板仍可读。
3. **绝不消费 `--dsw-specific-sidebar-fill`**——那是宿主左侧导航列专属令牌，皮肤按左导航语义覆盖它
   （半透明玻璃/主题色/transparent 都有），面板用了会失去填充或与标签令牌冲突。
4. **面板表面 = `var(--dsw-alias-bg-layer-1)`**。dsh-web-ui 皮肤中心 10 款皮肤全部覆盖此令牌，
   换肤自动跟随。
5. **文本密集表面（命令等宽块、输入框）消费 `--dsw-alias-bg-base` 时**，注意玻璃皮肤会把它设成
   `transparent` 或 alpha 0.16–0.7 的半透明值：CSS 直用没问题（文字下方有面板表面垫着），但若要
   **JS 读取计算值**（如动态着色），须复刻 better-sidebar 的 `effectiveTokenValue` 规则——
   `transparent` / alpha < 0.9 一律回退不透明底色（`src/client/theme.ts`，issue #90 的教训）。

### 1.2 令牌速查表（better-sidebar CSS 实证在用）

| 用途 | 令牌 |
|---|---|
| 底层背景 / 输入框 / 等宽块 | `--dsw-alias-bg-base` |
| 卡片/面板表面 | `--dsw-alias-bg-layer-1` |
| 弹层表面（右键菜单、确认弹窗、下拉） | `--dsw-alias-bg-layer-2` |
| 一级分隔线 / 卡片边框 | `--dsw-alias-border-l1` |
| 二级边框（面板外缘、hover 边框） | `--dsw-alias-border-l2` |
| 主文字 | `--dsw-alias-label-primary` |
| 次文字 | `--dsw-alias-label-secondary` |
| 弱文字（占位、计数、辅助说明） | `--dsw-alias-label-tertiary` |
| 主按钮文字（反色） | `--dsw-alias-label-primary-inverted` |
| 强调/激活文字 | `--dsw-alias-brand-primary` |
| 悬停背景 | `--dsw-alias-interactive-bg-hover` |
| 悬停强调背景（拖拽指示、焦点 outline） | `--dsw-alias-interactive-bg-hover-accent` |
| 按下/选中背景 | `--dsw-alias-interactive-bg-active` |
| 主按钮填充 / 悬停 | `--dsw-alias-button-primary-fill` / `--dsw-alias-button-primary-hover` |
| 危险（文字、删除确认、危险徽标） | `--dsw-alias-state-error-primary` |
| 警告文字 / 警告底 | `--dsw-alias-state-warn-label` / `--dsw-alias-state-warn-tertiary` |
| 成功 | `--dsw-alias-state-success-primary` |
| 遮罩（仅降级形态如需蒙层时；正常不加蒙层） | `--dsw-alias-bg-mask-1` |
| 等宽字体 | `--ds-font-family-code` |

### 1.3 深浅色与换肤侦测

- 宿主把主题决策投到 `body[data-ds-dark-theme]` 与 `html { color-scheme }`。
- 纯 CSS 消费令牌**无需任何 JS**——明暗切换、皮肤中心换肤全自动跟随。
- 只有 JS 必须读具体色值时（cmd-pad 目前无此场景），才用 MutationObserver 订阅
  `body[data-ds-dark-theme]` 属性变化（better-sidebar `subscribeColorScheme` 同款模式）。

## 2. 组件配方（与 better-sidebar 同款视觉）

以下是 better-sidebar CSS 里反复出现的固定搭配，cmd-pad 直接复用：

| 组件 | 配方 |
|---|---|
| 行项（分组行、列表行） | 默认 `label-secondary`；hover：`interactive-bg-hover` + `label-primary`；选中/按下：`interactive-bg-active` |
| 分组横条 chip（cmd-pad 分组区，2026-08-23 用户定稿布局） | `inline-flex` 横向排列于搜索框下方（容器 `flex-wrap:wrap`），圆角 6px、`padding:3px 8px`、名字 `max-width:120px` 截断省略号；交互态同「行项」配方；「▸ 更多（N）」chip 用 `border:1px solid border-l1`。~~「上次使用」slot~~ 已按用户定稿移除（调整记录 #17：打开抽屉直接定位上次使用分组，不再显示标签） |
| 次级按钮（复制/运行；运行按钮随 T07 功能恢复，2026-08-23） | `border: 1px solid border-l1` + `bg-layer-1` + `label-primary`；hover：`border-color: border-l2`（+ `interactive-bg-hover`） |
| 主按钮（保存等） | `background: button-primary-fill` + `color: label-primary-inverted`；hover：`button-primary-hover` |
| 弹层（右键菜单/确认弹窗/下拉） | `bg-layer-2` + `border: 1px solid border-l2` + 圆角 + 阴影；菜单项 hover：`interactive-bg-hover` |
| 危险命令确认弹窗的命令原文块（`.cmd-pad-modal-pre`，T07 2026-08-23） | 弹窗内等宽块配方（§1「命令等宽块」= `bg-base` + mono 字体）：`font-family` 用 `--dsw-alias-font-mono` 兜底链、`white-space:pre-wrap`、`word-break:break-all`、圆角 6px、`max-height:200px` 内滚动——全令牌，无新颜色 |
| 危险项（删除菜单项/危险徽标） | 文字 `state-error-primary`；需要底色时 `color-mix(in srgb, var(--dsw-alias-state-error-primary) 10%, transparent)` |
| 虚线提示框（「上次使用」slot） | `border: 1px dashed border-l2` + 弱化文字 `label-tertiary` |
| 空态/占位 | `label-tertiary`，居中，无图形 |
| 徽标 pill（危险标记） | 纯文字 pill：`state-error-primary` 文字 + 10% 同色底（color-mix） |

排版层级即语义（功能文档 §2.4 已定）：分组类型靠文字前缀（`项目：`/`上次：`）与
`label-primary` vs `label-secondary/tertiary` 的字色层级区分，不用图形符号。

## 3. 图标规范

### 3.1 cmd-pad 全局规则（用户定稿，功能文档 §2.4）

1. **不使用任何彩色图标，不使用 emoji**（`📁📌🕘` 之类一律禁止）。
2. 全插件仅保留 **2 处功能必需图形**：better-sidebar Tab 图标、搜索框放大镜。
3. 按钮一律纯文字：`复制` / `+ 添加`（`+` 是文字字符）；「更多」用纯文本字符 `▸`（「运行」按钮暂缓，随运行功能恢复，见 TASK.md 调整记录 #21）。
4. 状态色仅两处文本级用途：危险徽标（`state-error-primary`）、强调（`brand-primary`，仅激活态与主按钮）。

### 3.2 SVG 技术规范（与 better-sidebar 图标体系完全一致）

参照 `src/client/icons.tsx` 的固定形制：

- `viewBox="0 0 16 16"`，`fill="none"`，默认 size 16；
- **描边 `stroke="currentColor"`，`strokeWidth="1.5"`**，`strokeLinecap="round"` `strokeLinejoin="round"`；
- 圆角外框 `rx` 取 2–2.5；实心小块（如需要）用 `fill="currentColor" stroke="none"`；
- 颜色**只**来自 `currentColor`——颜色完全由外层 CSS 令牌决定，SVG 内不写任何色值；
- Tab 图标的 descriptor 形态：`icon: (size) => <Svg size={size} />`（React 桥接下用 `createElement`，
  或直接内联 SVG 字符串构建的 ReactNode）。

cmd-pad 的 Tab 图标：**命令列表符号**（已定稿 2026-08-23，调整记录 #23——用户反馈原 `>_` 终端造型
与内置 terminal 图标混淆）：rect 外框 + 提示符 `m4 5.75 1.5 1.5L4 8.75` + 两行命令线
`M7.75 7.25h3.75` / `M4 12h4.5`（React 桥接 `createElement('svg', …)`）；与内置终端（居中 `>_`
+ 顶部窄边窗口）明显区分。放大镜同理：圆形 + 短柄，1.5px 描边。

### 3.3 主形态宿主容器（T06 落地）

- 主形态 Tab 面板宿主 `.cmd-pad-tab-host`：`height:100%` + `display:flex; flex-direction:column`
  撑满 better-sidebar 面板内容区，内部复用抽屉同款面板骨架（`.cmd-pad-drawer-body` 布局类）；
- 主形态内容区与抽屉视觉完全一致（搜索/分组横条/卡片/弹窗/菜单/Toast），无任何新增视觉层；
- 「+ 添加」在主形态落在搜索行右端（抽屉在顶栏），类名同为 `.cmd-pad-add`。

## 4. DOM 寻址与层叠

1. **better-sidebar 的类名是 CSS Modules 哈希，不是契约**——cmd-pad 绝不引用它的类名；自己的类名加
   `cmd-pad-` 前缀防撞。
2. 稳定寻址面（仅调试/极端避让用）：`[data-dsh-better-sidebar]`（插件根）、`[data-dsh-panel]`（右面板）、
   `[data-dsh-bottom-panel]`（底面板）；角落按钮簇**无统一 data 锚点**——v0.15.1+ 才有
   `[data-dsh-toggle-cluster]`，v0.13.x 只有 CSS Modules 哈希类名（不可引用，见 §1），故避让走
   **双锚点**：优先 `[data-dsh-toggle-cluster]`，缺省在 `[data-dsh-better-sidebar]` 宿主内做
   几何探测（顶部 top≤40px 且右缘贴近视口右缘的可见按钮，取最右者，量其父容器）。
   - 避让动作（T01 实证 + T02 修复，见 TASK.md 调整记录 #6）：better-sidebar 在场但 cmd-pad
     走降级时，按钮簇（z-index 45，fixed top:3px right:10px）会盖住抽屉顶栏 ✕（抽屉 30）——
     **抽屉顶栏 ✕ 左移避让**：挂载时 + **每次抽屉打开时**探测按钮簇，右缘真实落在视口内时把
     顶栏 `padding-right` 置为 `视口宽 - 按钮簇左缘 + 8px`（`applyClusterOffset`，接入规范 §5.5）；
     浮动图标默认位于右下角，与右上角按钮簇天然不重叠。
3. **z-index 层级**（better-sidebar 实证）：面板宿主层 40、折叠按钮簇 45；DSH 浮层栈 100/1000+。
   - 降级抽屉：z-index **30**（低于 better-sidebar 面板，极端共存时不遮挡它；高于普通页面内容）；
   - cmd-pad 自身弹层（右键菜单/确认弹窗/Toast）：z-index **90**（低于 DSH 浮层栈，不抢宿主对话框）。
4. 桌面壳兼容：可点击 chrome（浮动图标、抽屉顶栏、右键菜单）加 `-webkit-app-region: no-drag`——
   无边框壳的顶部拖拽带会吞点击，普通浏览器下此属性惰性无害（better-sidebar 全 chrome 同款处理）。
5. 抽屉/浮动图标挂载点：`document.body` 下独立容器，带 `data-dsh-cmd-pad` 属性（自检与调试锚点）。
   - **降级抽屉为占用式布局**（T03 前体验修复，见 TASK.md 调整记录 #7）：打开时给 `#root` 注入
     `margin-right: calc(var(--dsh-sidebar-width,0px) + 抽屉宽)`——主页面（含对话输入框）左移让位，
     抽屉不遮挡内容，与 better-sidebar 的 layout-push 同款；关闭/卸载时移除（回退 better-sidebar
     变量驱动），窗口 resize 时重算；better-sidebar 完全不在场时同样生效（无动画但功能正确）。
   - **拖拽分栏**（调整记录 #8）：抽屉左缘 8px 把手（`.cmd-pad-drawer-resize`，col-resize、
     `touch-action:none`、全高），pointer 拖动调宽，clamp `[280, min(92vw, 视口-320)]`；拖动中
     `#root` transition 禁用（margin 即时跟随指针）、抽屉加 `[data-dragging]`；宽度
     localStorage 持久化（键 `dsh-cmd-pad:drawerWidth`，多标签页同源共享），刷新/重开恢复，
     resize 时超上限自动 clamp。

## 5. 双形态样式职责划分

| | 主形态（Tab） | 降级形态（抽屉） |
|---|---|---|
| 面板框架/圆角/边框/拖拽 | **better-sidebar 承担，cmd-pad 不写** | cmd-pad 自建（`bg-layer-1` + 左缘 `border-l2`） |
| 内容区（分组横条/卡片/搜索） | 同一份代码，100% 复用 | 同一份代码，渲染目标容器不同 |
| 浮层（菜单/弹窗/Toast） | 自建（弹层配方见 §2），挂 Tab 内容区内或 body | 自建，z-index 90 |
| 蒙层 | 无 | **无**（非模态，功能文档 §2.3） |
| 浮动图标 | **不存在** | 圆形按钮：`bg-layer-1` + `border-l2` + 单色 SVG |

主形态下**禁止**再渲染任何浮动元素——这是功能文档 §2.2 的硬规则，样式层不得破坏。

## 6. 验收清单（每次 UI 改动后过一遍）

- [ ] 无硬编码色值（grep `#`、`rgb(`、`hsl(`，命中必须能说明理由）
- [ ] 无 emoji、无彩色图标；图形仅 2 处且为 currentColor 单色 SVG
- [ ] 全部按钮纯文字
- [ ] 明暗切换 + 皮肤中心至少 2 款皮肤（含 1 款玻璃皮）目检
- [ ] 主形态下无自建浮层；降级抽屉非模态、无蒙层
- [ ] 类名全带 `cmd-pad-` 前缀；未引用 better-sidebar 任何类名
- [ ] z-index 符合 §4.3 层级
